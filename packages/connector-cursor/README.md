# @crosscheck/connector-cursor

The Cursor IDE connector (design: `docs/adapters/DESIGN-agent-agnostic.md` §3): short-lived `crosscheck cursor-hook <event>` processes over Cursor's **documented** hooks API — the same spool, the same budgets, the same fail-open-everywhere as the Claude connector. Hooks + MCP, **not** rules files (§3.3 rejects rules as an injection channel: gitignore-interplay drift and a second sanitize surface).

**Blocks 6 + 7 landed capture AND injection; 2026-08-28 added the DERIVE rungs** — Cursor now infers as well as reading and asking (see "What Cursor infers" below). Every handler answers valid, directive-free JSON on exit 0 — `{}` when there is nothing to say, or `{"additional_context": "<text>"}` when there is: the `sessionStart` briefing and the failure-matched hints, both rendered exclusively by the core renderers (`renderBriefing`, `renderClaimHint`/`renderPointerHint`) through this package's one composition point (`src/inject/output.ts`). That module is a registered **§4.4 render surface**, and its corpus adapters attack the **real emitted payload**: renderer → stdout JSON → decoded `additional_context`, so the quoted-data notice and the « » frame are proven to survive JSON encoding on every corpus payload.

## What works today

| Cursor event | Tier-0 mapping (§3.2) + injection (§3.3) |
|---|---|
| `sessionStart` | `registerSessionFlow` with `cur-<conversation_id>` (state **before** any append), `agent_kind` `cursor-ide` / `cursor-background`, honest `branch @ repo` title, `cursor_version` → sync-state for doctor, spool flush + reap on the spare budget. **Injection**: the briefing via the shared `assembleBriefing` flow (six parallel fail-open GETs, `MAX_BRIEFING_CHARS` ≈ ≤600 tokens), emitted as the documented `additional_context` output; solved-pointer deliveries recorded with deterministic ids (a restart's replay is a hub-side `duplicate`); background agents get **no** injection output |
| `afterFileEdit` | `file_path` → shared target flow (repo-relative, denylist, seen-set, secret-scan, cap); heartbeat (throttled), status → `implementing`; edit **content is never parsed** |
| `afterShellExecution` | failure fingerprint **only on an explicit exit marker** — see the honesty note below. No injection output (undocumented marker + undocumented channel would be tolerance stacked on tolerance) |
| `postToolUse` | heartbeat, spool flush; failure fingerprint from the documented JSON-stringified `tool_output` when it carries a non-zero `exitCode`; pays the ghost debt if `stop` has not. **Injection**: a detected failure runs the failure-matched hint (shared `selectAndRenderHint` flow, failure text as the **ephemeral** query — never stored or logged), delivered on this event's documented `additional_context` |
| `postToolUseFailure` | `error_message` → shared extractor → `fingerprint()`; interrupts and `permission_denied` are **not** failures. **Injection (open-q4, tolerant)**: same hint attempt; `additional_context` is emitted in the shared response shape although this event documents no output fields — a build that ignores it degrades silently, and the injection ledger records which event actually delivered |
| `beforeSubmitPrompt` | **capture only**: the derived-intent fire on the first substantive prompt. Answers no directives on any path — its documented output is `{continue, user_message}`, which can only BLOCK, and this connector never blocks |
| `stop` | the Tier-1 gate (turn count → transcript tail → fire) and the ghost debt; spool flush; **never** `followup_message` |
| `sessionEnd` | shared `endSessionFlow` (flush → marker → state delete → `end` or deferred) |

**Hint parity with the Claude connector** (same kit call, so parity is structural, and each is pinned through the cursor path in `test/injection.test.ts`): at most **1 hint per event** (the selector returns one selection), **`MAX_HINTS_PER_SESSION` = 5** per session, the **seen-set** persists in session state (a repeated failure never re-delivers), the **echo-exclusion** body hash lands in the per-repo delivered store, and every delivery ships one **`hint_deliveries`** row with a deterministic id. The one deliberate divergence: Cursor documents no injectable prompt-time event (`beforeSubmitPrompt` has no context output), so the query is the failure text instead of the prompt — the design's "hint delivered at the failure, not next prompt" case is the whole channel.

**Injection ledger**: every decision — delivered briefing/hint, suppressed attempt (`empty`, `background`, `silence`) — appends one line to `~/.crosscheck/state/cursor-injection.jsonl` (bounded, append-only, content-free). `crosscheck doctor` sums it, including delivered hints **per carrying event** — that per-event count is the §6-q4 instrument.

Not registered, deliberately (§3.2): `beforeReadFile` (full file content), Tab hooks, subagent hooks, `preCompact`, `afterAgentResponse`/`afterAgentThought`, `workspaceOpen`.

## What Cursor infers

Four capabilities, on the rungs Cursor's platform actually allows — declared as data in `src/capabilities.ts`, printed one line each by `crosscheck doctor`, and held to what the package really ships by `connector-core/test/derive-capability-registry.test.ts` (an undeclared trigger and an undelivered declaration are both a red build).

| Capability | Rung | Why |
|---|---|---|
| **intent** | full | `beforeSubmitPrompt` carries the prompt; the first substantive one fires the shared derived-intent worker |
| **ghost** | full | the debt a recorded intent opens is claimed on `stop` or `postToolUse`, whichever fires first — Cursor has no always-runs next-prompt event |
| **summarizer** | **reduced** | Cursor documents the transcript POINTER (`transcript_path`, `CURSOR_TRANSCRIPT_PATH`) and no transcript FORMAT, so the reader is shape-tolerant and says which shape decoded |
| **conference** | full | `crosscheck conference` is a command a human runs; nothing about it is host-specific |

**And every refusal is a doctor line, not a silence** — a decision nobody can find is indistinguishable from a bug nobody fixed:

- **pre-edit ask**: not possible. Cursor's `preToolUse` accepts `ask` in schema but enforces only a hard deny, and crosscheck never hard-blocks.
- **prompt-time injection**: `beforeSubmitPrompt` is capture-only; its output adds no context and can only block.
- **response-text capture**: `afterAgentResponse` stays unregistered — agent prose with no work anchor, and buffering a turn across Cursor's separate hook processes would need a standing content file the privacy rule forbids.
- **cloud and background agents**: `sessionStart`/`sessionEnd` are documented unavailable there; those runs register through the recovery path.
- **no transcript** (conditional): its own booked outcome and its own sentence — *this Cursor build provides no transcript — Tier-1 capture off; deterministic capture unaffected* — never a runner WARN, because no model ran.

Derived output is **derived**: `provenance: derived`, `captureMode: auto`, confidence clamped to the derived cap, forced in the shared core worker where neither the model nor this connector can choose them. Drafts are pointer-only until somebody promotes one with `review_draft`.

**Install**: `crosscheck init --cursor` — composes with the default Claude init; merges `.cursor/hooks.json` (non-destructive, explicit `timeout`, **never** `failClosed`) and `.cursor/mcp.json` (the shared `mergeMcpConfig` — same five diagnosis tools). Both files are repo-committed: install = the same one PR, teammates connect on `git pull` + `crosscheck login`. **Gitignore interplay** (the reason rules files were rejected, and it applies here too): if your repo gitignores `.cursor/`, un-ignore `hooks.json` and `mcp.json` — an ignored install silently works for exactly one person. Cursor hot-reloads both files in trusted workspaces; no restart.

**Doctor**: `crosscheck doctor` gains a cursor section — the derive rungs and refusals above, hooks registered (all eight, none `failClosed`), launcher health (a bare `crosscheck` on PATH is resolved *and* executed via `--version`; an absolute-path launcher is checked for existence and package-runner caches, not executed), mcp entry owned, last-observed `cursor_version` ≥ 1.7, the **contract-drift counters**, and the **injection state** — briefings/hints delivered and suppressed, with delivered hints broken down by carrying event.

**Contract honesty**: the payload schemas encode Cursor's *documented* hook API — the examples from [cursor.com/docs/hooks](https://cursor.com/docs/hooks) are checked in as fixtures with source + fetch date (`test/fixtures/cursor-contract/`, fetched 2026-08-18, re-read 2026-08-19). Where reality may differ, the code tolerates unknowns and **counts** what it cannot map: a payload missing a mapped field degrades silently (fail-open) and lands one line in `~/.crosscheck/state/cursor-drift.jsonl`, which doctor surfaces. Capture can degrade; it is never allowed to die silently.

## The afterShellExecution honesty note

The documented `afterShellExecution` input is `{command, output, duration, sandbox}` — **no exit code of any spelling**. Under the connector's conservative rule (an explicit failure marker must be present; "no such field" means "not a failure"), the documented shape can never prove a failure, so on paper this event captures nothing. The handler tolerates a numeric `exit_code`/`exitCode` as the marker if a real build sends one. The reliable documented failure signal is `postToolUseFailure` (`error_message`), plus a non-zero `exitCode` embedded in `postToolUse`'s `tool_output`.

## Manual dogfood — what only a real Cursor install can answer

Design §6 open questions 4 + 5 defer to verification on a real build. **The suites here pin the documented contract; they cannot pin Cursor's reality. Do not treat a green CI as that verification.** On a real Cursor (≥ 1.7) install, a human must run:

1. **Install**: `crosscheck login <hub>`, then `crosscheck init --cursor` in a hub-connected repo; open the repo in Cursor as a trusted workspace. Run `crosscheck doctor` — the cursor section must be all PASS.
2. **One session + one edit**: start an agent conversation, have it edit a file. Verify on the hub (`/ui` or `crosscheck status`): presence shows a `cursor-ide` session; the edited path appears as a target.
3. **One failing command**: have the agent run a failing build/test. Then check `crosscheck status`/the hub for an `error_fingerprint` target, and note **which event carried it** — this answers open question 4's neighbor: does the failure surface via `postToolUseFailure`, via `postToolUse` `tool_output`, or (if payloads carry an undocumented exit field) via `afterShellExecution`? Record the answer in the design doc.
4. **Feed + doctor**: `crosscheck doctor` again — `cursor version` must now show the observed build; `cursor contract drift` must be `none`. **Any drift WARN here means Cursor's real payloads differ from the documented contract** — that finding is the whole point of the tripwire; file it against the fixtures.
5. **Per-surface checklist (open question 5)**: repeat 2–3 once in the IDE and once with a background/cloud agent on the same repo, and tick off which of the eight events actually fired (the drift ledger plus hub records tell you). The docs claim near-full cloud support with `sessionStart`/`sessionEnd` deferred — verify, and update §3.2's table with reality. **Known consequence of the documented deferral**: `is_background_agent` rides only on the two session events, so a cloud run that never gets them registers via the recovery path and shows in presence as `cursor-ide`, not `cursor-background`, and its hub session ends only by staleness — expect exactly that on this step, and record whether the real build matches.
6. **Briefing delivery (Block 7)**: with a teammate session live on the hub (a second machine or a Claude Code session on the same repo), start a **fresh** Cursor conversation. The composer's initial context must show the crosscheck briefing (teammate line + the quoted-data notice). Then `crosscheck doctor`: `cursor injection` must count `briefings 1 delivered`. If the doctor counts a delivery but the model gives no sign of having seen it, that is a finding about `additional_context` semantics — record it (Composer context is a black box, §3.5; the ledger is the only delivery evidence we can produce). **How to read the counts**: the ledger is home-wide (it covers every repo on this machine), and a row is written when the hook composes its response — a crash between record and print can leave a counted delivery no model saw, so treat counts as a ceiling on delivery, exact under normal operation.
7. **Matched hint at a failure (Block 7 + open question 4 proper)**: have a teammate record a failure (their agent runs a failing build → their fingerprint + claims land on the hub), then reproduce the same failing command in your Cursor session. A hint pointing at the teammate's work should arrive at the failure. Then `crosscheck doctor`: the `cursor injection` line names **which event carried it** (`postToolUse ×N` vs `postToolUseFailure ×N`) — that per-event count IS the answer to open question 4; record it in the design doc. Also confirm whether the hint visibly reached the model **mid-turn** (documented: "injected after the tool result") or only next turn.
8. **Nothing appears when it must not**: (a) run the same failing command again in the same conversation — no repeat hint (seen-set); (b) set yourself presence-off / muted on the hub (`/ui` settings), start a fresh conversation and fail a command — **no briefing content about you appears for teammates and no hints are delivered against muted authors' work** (visibility is enforced hub-side; the connector proves only silence here); (c) `CROSSCHECK_DISABLED=1` in the environment — every hook answers `{}` instantly, ledger untouched. **What CI cannot prove**: all of 6–8. CI pins the documented contract against a fake Cursor; only a human on a real build can see the model act on injected context.

## Not covered (v1, said out loud — §3.5)

No async push into a live session; no tripwire (Cursor's `preToolUse` "ask" is unenforced and hooks fail open — a soft gate must not impersonate a hard one); no statusline; Composer context is a black box; Tab/Inline edits invisible; Cursor **CLI** users get the ACP proxy instead (`crosscheck acp -- cursor-agent acp`); `state.vscdb` is never read (the documented `transcript_path` is the sanctioned channel and the Tier-1 rung uses it).

## Privacy (Tier-0, pinned)

Paths and fingerprints travel; content never does. The `edits[]` old/new strings, terminal `output`, `tool_output` bodies, `error_message` detail and `user_email` are never stored, spooled, or logged — failure text leaves the machine in exactly two forms: its `sha256:` fingerprint, computed by the same extractor + normalizer as every other connector (`test/parity.test.ts` closes the cursor == claude == acp triangle), and (Block 7) the EPHEMERAL hint query — sent over the wire to the hub you logged into, never stored or logged on this side, and **refused outright when the text trips the same secret scan that gates capture** (`containsSecret`: a hit means silence, never redact-and-send; `test/privacy.test.ts` pins this at the wire). Enforced three ways: a sentinel sweep over every file the connector writes, a wire-level sweep against a live recording hub, and a structural pin that the source never names the content-field accessors.

**Two pins were NARROWED when the derive rungs landed — narrowed, never deleted, each replaced by a stricter true statement with its own test.** The **prompt** is read (it is the only thing `beforeSubmitPrompt` carries) and goes to exactly one 0600 file that the detached worker unlinks in `finally`: `test/privacy.test.ts` names that file, proves the prompt reaches nothing else, and proves it is gone once the worker has run. **`transcript_path`** left the banned-token list for a SCOPED list: it may be named in `src/payload.ts`, `src/derive/transcript.ts` and `src/derive/triggers.ts` and in no other module — asserted as an exact set, so a module that stops needing it must leave the list too. The path itself is never stored or printed; doctor says whether a transcript was available, never where it is.
